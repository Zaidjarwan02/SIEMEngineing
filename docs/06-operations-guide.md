## Logging in

1. Open http://192.168.1.212:5601 in a browser.
2. Enter the tenant username and password.
3. Kibana opens the **space selector**. You will see exactly two spaces:
   - **Default** — the shared "general" space, **read-only**
   - your own tenant space (`greencircle` or `tkt`)
4. Choose your tenant space to do work. Choose **Default** to view shared dashboards and
   the shared prebuilt detection rules.

You will **never** see the other tenant's space. Manually browsing to it returns
**403 Forbidden**.

> **Why the selector?** Kibana shows the selector when an account can access more than one
> space. Before Default was shared, each user had one space and was taken straight to it.

### The shared Default space (read-only)

Default is the common area for all tenants. In Default you can:

- view shared dashboards and visualizations;
- browse the full prebuilt detection-rule set (2,062 rules, all enabled);
- **view the shared cross-tenant alert list** (Security → Alerts);
- read other shared saved objects.

The Default alert view is fed by the Default space's global rule set. It shows
alerts for every tenant, but the underlying tenant data stays isolated. Both
tenant accounts have read-only access to those alerts.

In Default you **cannot** create, edit, disable or delete anything — those actions
return **403 Forbidden**. You also cannot acknowledge, close, or change the status
of a Default alert. All content changes must be made by the administrator, or by a
tenant inside its own space.

### How to view all tenants' alerts

1. In the space selector, choose **Default** (the shared space).
2. Open **Security → Alerts**.
3. The list is the shared cross-tenant alert view. Use the time picker and filters
   as usual.
4. The alerts are **read-only** for tenant accounts. To triage or change status,
   work in your own tenant space, or ask the administrator.

> The Default list and your tenant-space list are separate alert stores. An alert
> generated by a Default rule is visible in Default; an alert generated by your
> tenant-space rule is visible in your space. The Default global rule set is what
> gives everyone the common all-tenant view.

### If you see a 403 right after login

The account is missing its space privilege. Contact the administrator; do not try other
accounts. The expected role grants are `space_all` on exactly one tenant space and
`space_read` on `space:default`.

## What you can do in your space

| Area | What it is for |
|------|----------------|
| **Discover** | Search and filter your logs/metrics using the pre-built data views |
| **Dashboards** | Create and share dashboards scoped to your tenant |
| **Visualize Library** | Build charts from your data views |
| **Alerting / Rules** | Create detection and threshold rules; alerts land in your tenant's alert index |
| **Stack Management → Data Views** | See the tenant-scoped data views (do not create broad patterns) |

### Available data views

**GreenCircle (`grcico-com`)**

- `GreenCircle Logs` → `logs-*-greencircle*`
- `GreenCircle Metrics` → `metrics-*-greencircle*`
- `GreenCircle Custom (grc-*)` → `grc-*`

**TKT (`tkt-org`)**

- `TKT Logs` → `logs-*-tkt*`
- `TKT Metrics` → `metrics-*-tkt*`
- `TKT Custom (tkt-*)` → `tkt-*`

Use these data views. A broad `logs-*` pattern will still be filtered by Elasticsearch to
your authorized data, but the tenant-scoped views are clearer and faster.

## Common tasks

### Search your logs

1. Open **Discover**.
2. Pick your tenant's **Logs** data view.
3. Set the time range and use KQL, e.g. `event.action: "login"` or `host.name: "server1"`.

### Create a dashboard

1. Open **Dashboards → Create dashboard**.
2. Add visualizations built on your tenant data views.
3. Save. The dashboard is stored only in your space.

### Work with the enabled rule set

All 2,062 prebuilt rules are already enabled in your space. You can:

1. Open **Security → Rules** (or **Stack Management → Rules and Connectors**).
2. Review the rule list, execution status and last response.
3. Enable/disable individual rules **in your own space** if a rule is too noisy.
4. Create your own rule while inside your tenant space.

Alerts generated by your space's rules are written to
`.alerts-security.alerts-<your-space>*` and are visible only to your tenant.

> Many prebuilt rules show `Warning` or `Failed` because the integration or index
> they expect is not installed, or because the rule's API key is scoped to your
> tenant. That is normal in this lab and does not mean your data is exposed. The
> shared Default space has its own global copy for the all-tenant alert view.

### Change your password

Ask the administrator to run:

```bash
curl -s -u 'elastic:<admin-password>' -H 'Content-Type: application/json' \
  -X POST 'http://127.0.0.1:9200/_security/user/grc_user/_password' \
  -d '{"password":"NEW_PASSWORD"}'
```

Kibana does not expose self-service password change for these native users in this setup.

## What you cannot do

- Open the other tenant's space.
- Create, edit, disable or delete anything in the shared Default space (read-only).
- Acknowledge, close, or write the shared Default alerts.
- Read or write another tenant's indices, data streams, or alerts.
- View cluster health, security users, or index management.
- Create indices outside your tenant namespace.

If you need any of these, raise a request with the platform administrator.

## Data availability

Fleet agents write to data streams named:

```
logs-<dataset>-<namespace>
metrics-<dataset>-<namespace>
```

For GreenCircle the namespace is `greencircle`; for TKT it is `tkt`. If a data view shows
no results, the agent may not be enrolled or may be writing to a different namespace.
Check with the administrator.

## Troubleshooting

| Symptom | Likely cause | Action |
|---------|--------------|--------|
| 403 immediately after login | Missing space privilege | Administrator fixes the role |
| Login page loops | Wrong password or disabled user | Verify credentials; ask admin |
| Data view shows "No results" | No data ingested yet, or wrong time range | Check time range; ask admin about agent status |
| "Forbidden" when saving in Default | Default is read-only for tenants | Switch to your own tenant space to make changes |
| Rule shows `Warning`/`Failed` | Missing integration/index, or tenant-scoped rule API key | Expected in this lab; check the rule's expected data source |
| Default alerts list is empty | No Default rule has produced an alert yet, or no matching data | Check the Default rule execution; ensure data uses standard `logs-<dataset>-<namespace>` names |
| Slow UI | VM memory pressure (no swap) | Report to administrator |
